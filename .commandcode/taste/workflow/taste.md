# Workflow
- Prefers to test web app deliverables manually in a browser: after building, spin up a local dev server and share the URL rather than relying only on automated verification. Confidence: 0.8
- When the user reports a bug, they expect the fix to be verified empirically, not just reasoned about: confirm correctness quantitatively (e.g., statistical checks over hundreds of trials, real-browser DOM/computed-style assertions), because they have caught wrong assumptions before. Confidence: 0.8
- When a previously-reported bug persists after a claimed fix, the user re-reports it and explicitly asks the assistant to dig for the real root cause ("I think there must be a bug. Try to figure it out") — expects a fresh deep investigation (e.g., re-reading the logic, simulating the exact scenario) rather than re-tuning constants of the prior approach. Confidence: 0.7
- Prefers to enumerate feedback first and have the assistant track it in a task list, explicitly instructing the assistant NOT to start implementation until given the go-ahead. Confidence: 0.8
- Reports bugs as concrete observed-vs-expected pairs with exact numbers (e.g., "I see 3 on the dice and it says 4; I see 2 and it says 5"), often giving two examples per report, and expects issues to be reproduced precisely rather than described vaguely. Confidence: 0.6
- When handing over a batch of bug reports, expects the assistant to group them by common root cause ("there are common themes") and fix the underlying themes systematically rather than addressing each symptom as an isolated one-off. Confidence: 0.6
- Prefers fixes that are structurally correct (e.g., building the exact dual of a solid, canonical coordinates, forcing faces coplanar by construction) rather than cosmetic patches — recurring visual bugs are usually geometry/rendering-root-cause problems. Confidence: 0.75
- Values rendering approaches that are robust across environments: when a CSS 3D technique composites unreliably (e.g., preserve-3d + clip-path shows overlapping/see-through faces in some browsers), prefers a plain 2D-projected render that is guaranteed to look the same everywhere, including during animation. Confidence: 0.75
- Prefers to host static web apps on GitHub Pages with the source in a GitHub repo and an automated GitHub Actions deploy workflow (triggered on push to main) rather than manual deployment. Confidence: 0.6
- When reporting mobile layout bugs, gives explicit reproduction guidance — names a device size to emulate (e.g., "emulate it on iPhone SE size") and states their own device (e.g., Pixel 8) — and expects the fix to be verified at both the suggested emulated size and their actual device dimensions before shipping. Confidence: 0.7
- Corrects the assistant when a fix is built on a mechanism that contradicts the reported symptom's timing (e.g., adding a settle-window for long shakes when the user reports a single ~100ms shake double-fires) — expects the over-engineered mechanism to be discarded and the minimal fix matching the observed behavior (plain debounce + always-refreshed baseline) to be restored. Confidence: 0.6
